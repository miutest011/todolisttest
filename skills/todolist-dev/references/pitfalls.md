# 踩过的坑

每一条都真实付出过时间。动手之前扫一眼，比事后查一下午划算。

## 缓存：你改的代码没生效

**症状**：改完代码刷新，看到的还是旧行为。于是开始怀疑自己写错了，查半天，
最后发现代码根本没跑。这个坑在这个项目里连续踩过**四次**。

三个来源，都要防：

1. **Service Worker 缓存**——`sw.js` 会把文件存到本地
2. **浏览器的启发式缓存**——`python3 -m http.server` 不发缓存头，浏览器就自己决定缓存
3. **改完忘了升版本号**——手机上那份 App 会一直用旧缓存

现有的四层防护，别拆：

- `tools/dev-server.py` 明确发 `Cache-Control: no-store` ← **本地开发只用这个起服务器**
- `tools/test.html` 动态加载脚本时给每个都带 `?t=时间戳`
- `sw.js` 里带查询参数的请求一律放行
- `sw.js` 在 localhost 下走网络优先，线上才是缓存优先

**改完代码记得 `sw.js` 里 `VERSION` 加一**，否则手机上不会更新。

顺带一个自动化工具的坑：**用浏览器工具 `navigate` 到同一个网址不会真的重新加载**，
得加个变化的查询参数（`?t=...`）或显式调 `location.reload()`。

## 时区：`iso.slice(0, 10)` 是错的

按天分桶时不要从 ISO 字符串里截前 10 位，那是 UTC 的日期。
本机在 UTC-7 时，本地时间 9 月 6 日晚上 11:30 的 ISO 字符串是 `2026-09-07T06:30:00Z`，
截出来是 9 月 7 日——用户会看到自己昨晚的打卡记在了今天。

正确做法是用本地的年月日拼：

```js
function logDateKey(iso) {
  const d = new Date(iso);
  const pad = (n) => String(n).padStart(2, '0');
  return `${d.getFullYear()}-${pad(d.getMonth() + 1)}-${pad(d.getDate())}`;
}
```

同样地，**从用户填的"12:00"构造时间时要按本地时间构造**，别拼成 UTC 字符串。

测这类功能时，测试数据要凌晨和深夜各来一次（见 `testing.md` 的"侥幸通过"）。

## 手机上和电脑上不一样

用户主力是 iPhone，**所有交互都以手机为准**。已经付出过代价的几条：

- **没有 hover。** 靠 hover 才显示的按钮在手机上等于不存在。
  区分设备用 `@media (hover: hover)` / `(hover: none)`，不要用屏幕宽度猜。
- **一行里只放一个主要动作。** 最初"点文字改名、点空白进详情页"，
  用户实测两天的反馈是"经常误触成编辑文字"——因为文字占了一行大半面积。
  改名后来统一挪到详情页标题和 ⋯ 菜单里。
  **判断方法**：如果一个动作的热区小于整行的一半，它就不该和另一个动作共存一行。
- **HTML5 拖放 API 在移动端不工作。** 用 Pointer Events 自己实现：
  触屏上长按约半秒才开始拖（直接滑动应该是滚页面），鼠标上移动超过阈值就开始。
- **拖动要有"浮起来"的反馈。** 用户的原话是"类似苹果桌面上长按后拖 App"——
  做法是克隆一份跟手的副本浮在上面，原位置留空。没有这个就会被说"不丝滑"。
- **拖完那一次点击要拦掉**，否则松手就顺带进了详情页（`suppressNextClick`）。
- 触摸目标别小于 44×44，视觉上可以小，热区要够。
- 安全区用 `env(safe-area-inset-*)`，否则底部标签栏会被 iPhone 的横条压住。
- **页面被放大、和屏幕对不上**，通常不是双指缩放，而是两种"自动放大"：
  **输入框字号小于 16px 时 iPhone 一点进去就放大、而且不缩回去**（所有输入框统一用 `--text-input: 16px`，新加输入框别用别的字号）；
  **连点两下会放大**（`html { touch-action: manipulation }`，打卡连点数字最容易触发）。
  viewport 里的 `user-scalable=no` Safari 会无视，只能靠 `gesturestart` 里 `preventDefault` 拦双指——这一条只能在真 iPhone 上确认。
- **浮在底部的东西（+ 按钮、撤销提示）会互相压住，也会挡住列表最后一项。** 加浮动元素时：列表底部留出它的高度；
  同一高度上还有别的浮动元素的话，错开上下位置（只错开左右不行，名字一长就压上了）。
- **需要打字的弹出层放在屏幕上方，别贴底。** iPhone 网页弹键盘时，贴底的东西常被挡住或跳来跳去。
- **弹出键盘时，贴底的标签栏、+ 按钮会被顶到键盘上面**，挡住正在输入的地方（用户实拍截图发现的）。
  做法：光标在输入框里时给应用加 `typing`，CSS 在 `@media (hover: none)` 里把它们藏起来。
  判断"光标离开"要看 `focusout` 的 `relatedTarget`（焦点要去哪），并且每次 `render()` 结束再对一遍——
  重画删掉的输入框不一定发 `focusout`，不对一遍的话标签栏会一直藏着回不来。
- **iPhone 会照着贴在页面最顶上的东西给状态栏上色。** 盖满全屏的暗色遮罩会把状态栏染灰，关掉后有时变不回来。
  所以：遮罩从状态栏下面开始（`top: env(safe-area-inset-top)`）；**钉在屏幕上的页面容器一定要有底色**，别透明。
  用户截图里的灰正好是遮罩叠在白底上的颜色，靠这个认出来的——截图里颜色不对劲时，先算算它是不是某一层半透明叠出来的。
- **让某一块跟着手指移出屏幕时，记得把整个网页横向夹住。** 详情页往右滑时会伸到屏幕外面，不夹的话整页就能跟着横着拖（左右晃、右边露白）。
  夹的写法有两个讲究：**写在 `html` 上**（写在 `body` 上只夹住 body 自己那一块，整页照样能拖，实测过）；**用 `overflow-x: clip` 而不是 `hidden`**——
  `hidden` 会让 `html` 变成一个可滚动的盒子，iPhone 上容易连累上下滚动，`clip` 只是把伸出去的部分切掉。
- **手势方向要照大众习惯来，别自己发明。** 详情页返回一开始做成"往下拉"，规则和手感都做完了，用户一用就说"不太顺"，改成"手指从左往右滑"（iPhone 系统返回的方向）才对。**这类问题测试和截图都发现不了，只有真人用才知道**——所以新手势先照最常见的做法做，别先做自己觉得巧妙的那个。改方向时记得回头看变异清单：有的条目会失去意义（见 `tools/README.md`）。
- **滑动手势和页面滚动、长按拖动抢同一根手指。** 做右滑返回、左右滑切换标签时定下的做法（`trackSwipe`）：
  手指走过几像素才定方向，**定了这一下就不改**（边滑边改主意，页面会一会儿滚一会儿不滚）；归手势的那一下在 `touchmove`（`passive: false`）里 `preventDefault` 拦住滚动，不归的一律不拦；长按拖动已经开始（屏幕上有 `.drag-ghost`）就不当成滑动；按在输入框里、正在打字、菜单开着时不算手势。
  **手势的真实手感只能在真 iPhone 上确认**——测试能管规则（往哪滑、滑多远算数），管不了"跟不跟手""和系统回弹打不打架"，汇报时要说清楚。
- **想让页面像 App：整个网页别滚，只让列表那一块滚。** 整页滚的话标签行会跟着走、右边有滚动条、滑到头整页弹一下，
  而且 iPhone 上整个网页的滚动条用 CSS 藏不掉。做法见 `createScrollingPage()`（`.page` 钉在屏幕上，`.page-scroll` 自己滚）。
  **连带要改的**：拖到屏幕边上自动滚动，得滚 `.page-scroll` 而不是 `window`；列表底部要在滚动区里让出标签栏和 + 按钮的高度。
- **手机专用的 `@media` 规则要写在它要覆盖的那条后面。** 同样具体的两条规则，写在后面的赢。
  写在文件开头的"手机上的调整"里，会被后面的基础规则悄悄盖掉——测试页是电脑宽度，所有测试都绿，只有手机截图看得出来。
- **改了"展开 / 收起"的规则，要回头看拖拽还能不能用。** 改成一次只展开一个清单后，别的清单全收着，
  而任务只能拖进"有任务列表"的清单——等于再也拖不进别的清单了。收起的清单里放了一个看不见的空列表（`collapsed-drop`）接住拖进来的任务。
- 本项目的浏览器预览在"手机尺寸"下，真实点击（`computer` 点击）常常到不了页面——连原本好用的底部标签都点不动。
  遇到"点了没反应"先拿一个已知好用的按钮做对照，确认是不是预览工具的问题，别急着改代码。

## 装成 iOS 应用（ios/ 那层壳）

做这层壳只为一件事：**提醒在 app 关着时也能响**。网页应用做不到，浏览器不让网页在后台跑——
这不是能力问题，是系统规定，别浪费时间在网页那边找办法。

几条已经付出过代价、或者会付出代价的：

- **网页里那半要能单独测。** 外壳（Swift）没有自动测试，所以尽量把逻辑留在网页这边：
  "哪些提醒该交、什么时候交、交什么内容"全在 `app.js` 里算好，外壳只负责照单办事。
  `native.js` 也属于网页这半 —— 它有测试，而且在普通浏览器里什么都不做。
- **应用里的数据和 Safari 里的是两份。** 浏览器按"来源"分数据，换了壳就是换了来源，
  所以要有导出 / 导入，否则用户在网页版攒的东西搬不过来。
- **网页文件别用 `file://` 加载。** 那样引擎会把它当成没有来源的页面，`localStorage` 不保证留得住。
  壳里自定义了一个地址（`todolist://app/index.html`）就有了正经来源，数据和普通网站一样存得住。
- **iOS 一个应用最多排 64 条等着弹的通知**，多的直接丢掉。所以只交最近的 60 条。
- **免费 Apple ID 签的应用 7 天后打不开**，要连电脑重装（数据不丢）。开始做之前就要跟用户说清楚，
  别等装完才发现。
- **图标别放进 `Assets.xcassets`。** 编译图标目录要用 Xcode 的 `actool`，它在"只装了 Xcode、没装模拟器运行环境"的机器上
  直接报 `Failed to locate any simulator runtime`——命令行和 Xcode 里按 ▶️ 都过不去，要么下 7GB 的模拟器，要么绕开。
  绕法：几张 PNG 直接进应用包，在 `Info.plist` 的 `CFBundleIconFiles` 里列出来。
- **没有真机也能验证：用模拟器。** 本地通知在模拟器里是真弹的，连"应用已杀掉"这种情况都能验
  （做法和命令见 `ios/README.md` 的"在模拟器里验证"）。**截图要掐着点**，横幅几秒就收走，晚一分钟截就只剩桌面、
  会误判成"没弹"——真踩过，靠 `log show` 里的 `Deliver local notification` 才看清事实。**手势和键盘这类手感，模拟器不算数。**
- **Xcode 要比手机系统新**，否则连不上手机（`developer disk image could not be mounted`）。
  而新 Xcode 又要求新 macOS，所以"装到手机上"这一步可能牵出系统升级，**提前跟用户说清楚这条依赖链**。
- **写完 Swift 一定要真的编译一次**：`xcodebuild -project ios/TodoList.xcodeproj -target TodoList -sdk iphoneos -configuration Debug CODE_SIGNING_ALLOWED=NO CODE_SIGNING_REQUIRED=NO build`。
  不签名也能编过，能挡住语法错、工程配置错这类问题 —— 这是 Swift 那半唯一能自动验证的东西，别省。
  没装模拟器运行环境时只能按 `-sdk iphoneos` 编（模拟器那条路走不通）。

## 嵌套点击：外层会跟着响应

一行任务上有勾选框、置顶按钮、⋯ 菜单，整行本身还要能点进详情页。
**内层的处理函数里必须 `e.stopPropagation()`**，否则点勾选框会顺带跳进详情页。

这类 bug 每次都长一样，所以每个新的嵌套点击目标都值得配一条
"点它不该触发外层"的测试。已经有好几条了，都是补漏时加的。

## 认 id，不认名字和下标

- **名字会变。** 待办用清单名做关联，代价是每次改名都要连带更新任务归属和折叠记录，
  漏一处任务就从界面上"消失"了。打卡后来用 id，改名就完全不用同步。
- **下标会移动。** 拖拽、排序、过滤之后，之前记的下标就指向别人了。
  `data-index` 这类属性每次重画都要重设——有一次 `createTodoItem` 停了这一行，
  拖拽就**静默地不保存**，界面看着还是对的。

**新数据一律带 id。**

## 加了筛选之后，"严格校验"会变成"静默失败"

`applyCategoryOrder` 只接受"和现有清单一模一样、只是顺序不同"的列表，这是为了防丢数据。
可一旦页面加了标签筛选，页面上只看得到一部分清单，拖完交上去的列表就"少了几个"——
**校验拒绝写入，不报错，用户拖完一松手又弹回去了**。上移下移也一样：数组里的邻居可能正好是看不见的那个。

**判断方法**：给列表加筛选、搜索、分组之前，把所有"读页面上有哪些元素"的地方找出来
（拖拽提交、上移下移、按位置算落点），确认它们在"只看得到一部分"时还对。
做法是把看得见的新顺序填回它们原来占的位置，看不见的原地不动（`mergeVisibleCategoryOrder`）。

## 去掉一段文字时，看看它是不是在"撑着"排版

新建任务面板去掉"放进清单"那行小标题后，一排清单直接贴在了输入框底下——原来的间距是那行字的上下留白给的。
测试全绿（它们不看间距），是手机尺寸截图看出来的。**删掉界面上的元素之后，截图看一眼它周围**。

## 编辑代码前先读

有两次凭记忆写 `old_string` 去改文件，都失败了——记忆里的空格、标点和实际文件对不上。
**改之前先 Read 或 grep 出真实内容**，别省这一步。

## 数据迁移：老字段要删掉

从 `done: true/false` 迁到 `status: 'active'|'done'|'abandoned'` 时，
如果两个字段都留着，早晚会对不上，而且是那种极难查的 bug。
迁移逻辑放在读数据的地方，并且**补一条喂它老格式数据的测试**。

## 成对的魔数

月历格子 26px 和外面的手写圈 36px 必须一起改。这种隐性关联**在两处都写注释说明**，
不写的话三个月后一定会只改一个。

## 变异测试本身可能是无效的

改坏了代码但测试全绿时，先确认你的破坏真的造成了可观察的差异。
详见 `testing.md`。
